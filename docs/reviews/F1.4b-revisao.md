## Ajustes feitos pelo revisor (pequenos, no mesmo commit da revisão)
1. `SensorRegistry`: a exceção para `:` era um caso especial pelo prefixo "WEAR AND TEAR". Agora a regra é genérica: `:` é proibido só quando `PerEngine = true` (o layout põe o índice do motor); índice fixo em sensor não-por-motor é permitido. Teste `Validate_FixedIndexOnNonPerEngineSensor_IsAllowed`.
2. Spike por nome: o formato documentado no SDK é `WEAR AND TEAR LEVEL:'PISTON_ENGINE'_n` (não `:PISTON_ENGINE`). Corrigido no registro, no inventário e no script.
3. `native_wear_summary`: quedas menores que 1e-6 por amostra eram ignoradas (o desgaste lento real do C152 é ~2e-6 por amostra) e qualquer subida mínima contava como reinício. Agora toda queda soma e só subida > 0,005 (`RESTART_JUMP`) é reinício; subida menor é ruído e só move a base. Teste `test_native_wear_slow_drops_and_noise`.

## Fatos do SDK registrados na revisão
- Sintaxe por SimConnect: ID do componente como índice (`WEAR AND TEAR LEVEL:39`). O segundo parâmetro (ex.: motor 2) só está documentado em RPN (`2 (A:1:WEAR AND TEAR LEVEL:39, Percent)`); para o SimConnect, não. O voo decide se `:39:1` é aceito.
- Coluna "Settable" do SDK: `LEVEL`, `WEAK VALUE`, `IS WEAK`, `IS FAILED`, `EXPOSED PARTS *` são **só leitura**.
